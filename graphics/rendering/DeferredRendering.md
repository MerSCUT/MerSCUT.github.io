# 延迟渲染

Deferred Shading / Rendering. 是目前工业级引擎的常用**光栅化渲染架构**.

更传统的架构是**前向渲染**.



## 前向渲染

该管线的逻辑是**画一个物体就计算一次光照**.

但存在**过度绘制**的问题 : 如果先画**后方**的物体并计算光照, **前方**的物体会在结果中覆盖计算结果, 那么后方物体的渲染性能就被浪费了.

以及**光源数量受限** : $N$ 个物体 $M$ 个光源的场景, 需要 $O(MN)$ 的复杂度. 过大的 $M$ 会直接使性能爆炸.



## 延迟渲染

基于此, 延迟渲染将渲染管线分为两个部分 :

1. **渲染不透明物体, 且不计算光照**. 仅计算每个像素所绘制物体的 :

   1. 3D 坐标
   2. 深度
   3. 法线方向
   4. 基础颜色
   5. 粗糙度等其他信息.

   上述信息被统一存储到一个**Geometry Buffer** 中. 

2. **光照处理** : **对屏幕上的每一个像素**, 通过 G-Buffer 获取其信息, 并结合场景光源信息进行**光照计算**.

   1. 值得注意的是, 这一步**仅在屏幕空间**完成.



当然缺点也有 :

- GPU 显存压力极大, 因为要频繁读写巨大的 G-Buffer .
- 与 MSAA 不兼容, 只能与 FXAA, TAA 等后处理方案兼容. 
  - 光照处理部分本身也是后处理.
- 半透明物体无法处理. 现代常用解决方案是先解决所有不透明物体, 再切换到**前向渲染**管线上绘制半透明物体.
