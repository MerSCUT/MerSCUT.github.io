### 一、 渲染器项目与离线渲染深度追问

这一部分面试官会着重考察你对核心代码的掌控力以及对渲染算法的理论理解程度。

- [x] **重要性采样(IS)** : 详细推导 IS 的数学原理.
- [x] **多重重要性采样 (MIS)：** 详细推导 MIS 的平衡启发式 (Balance Heuristic) 和权重计算公式。在实际渲染场景中，它如何有效解决单独依赖光源采样或 BRDF 采样带来的高方差（噪点）问题？
- [x] **BVH 加速结构与 SAH：** 表面积启发式 (SAH) 的代价函数是如何定义的？在构建 BVH 树时，如何高效地划分节点边界以最小化该代价函数，时间复杂度是多少？
- [x] **蒙特卡洛积分器：** 蒙特卡洛路径追踪中，如果光线击中了一个发光面积极小的光源，或者是一个纯粹的镜面 (Perfect Specular)，会产生什么问题？渲染管线中是如何处理这些奇异点 (Singularity) 的？
- [x] **低差异序列 (QMC)：** 相比于传统的伪随机数生成器 (如 `rand()`)，为什么低差异序列 (例如 Sobol 序列) 在计算高维蒙特卡洛积分时能显著提高收敛速度？
- [x] **多线程调度：** 使用 C++ 多线程在进行分块渲染 (Tile-based Rendering) 时，如果某些图像块（例如玻璃材质密集的区域）计算耗时极长，如何处理线程间的负载不均衡问题？

### 二、 图形学基础与实时渲染管线

互娱的引擎或图形开发岗位，对现代游戏引擎的实时渲染技术有着严格的要求。

- [x] **渲染方程：** 推导并解释渲染方程 $L_o(p, \omega_o) = L_e(p, \omega_o) + \int_{\Omega} f_r(p, \omega_i, \omega_o) L_i(p, \omega_i) (\omega_i \cdot n) d\omega_i$ 中各个物理量的含义。
- [x] **PBR 材质模型：** 详细说明基于微表面的 BRDF 模型 (Microfacet Model) 的三大核心组件（D 项法线分布函数、G 项几何遮蔽函数、F 项菲涅尔方程），以及它们各自代表的物理意义。
- [x] **渲染路径：** 延迟渲染 (Deferred Rendering) 相比正向渲染 (Forward Rendering) 解决了什么核心问题？它存在哪些固有的瓶颈（如内存带宽消耗、半透明物体渲染、硬件抗锯齿）？
- [x] **阴影生成：** Shadow Mapping 中常见的伪影（如 Shadow Acne 和 Peter Panning）产生的原因是什么？如何通过 PCF 或 PCSS 来实现物理上更准确的软阴影？
- [ ] **抗锯齿技术：** MSAA (多重采样抗锯齿)、FXAA (快速近似抗锯齿) 和 TAA (时域抗锯齿) 在原理上有什么本质区别？TAA 在快速移动的画面中遇到的 Ghosting (拖影) 现象通常如何通过历史重投影解决？
- [x] **深度测试优化：** 什么是 Early-Z？在什么情况下（例如 Alpha Test 或手动修改深度）Early-Z 优化会被禁用从而导致性能下降？

### 三、 空间几何与数学推导

强大的数学直觉是图形学工程师的加分项，面试官非常喜欢考察矩阵与变换。

- [x] **相交测试：** 解释 Möller-Trumbore 射线与三角形求交算法的数学推导过程。相比于先求交平面再计算重心坐标的方法，它有什么性能优势？
- [x] **旋转与插值：** 为什么在骨骼动画或相机控制中更倾向于使用四元数 (Quaternion) 而不是欧拉角 (Euler Angles)？请解释万向节死锁 (Gimbal Lock) 发生的代数和几何原因。
- [x] **空间变换：** 推导透视投影矩阵 (Perspective Projection Matrix)。经过透视除法 (Perspective Divide) 后，NDC 空间下的 $Z$ 值分布是线性的吗？这种非线性分布会导致什么渲染问题？
- [x] **坐标系变换：** 将法线从模型空间转换到世界空间时，为什么有时需要乘以模型变换矩阵的逆转置矩阵 (Inverse Transpose Matrix) 而不能直接使用模型矩阵？

### 四、 C++ 底层机制与性能优化

游戏引擎是性能敏感型软件，对底层系统的理解决定了代码的上限。

- [x] **多态与性能：** C++ 虚函数表 (vtable) 和虚表指针 (vptr) 的内存布局是怎样的？在高性能的逐像素渲染循环中，频繁调用虚函数会带来怎样的性能惩罚？
- [x] **内存管理：** 图形引擎中通常会避免使用原生的 `new`/`delete`，而是自定义内存池或分配器 (Memory Allocator)。这样做主要是为了解决哪些痛点？
- [ ] **数据对齐：** 什么是内存对齐 (Memory Alignment)？在将数据从 CPU 传递到 GPU（例如构造 Uniform Buffer Object）时，为什么严格遵循内存对齐规则至关重要？
- [ ] **CPU 缓存：** 简述缓存局部性 (Cache Locality)，并解释它如何影响遍历大型空间数据结构（如 BVH）时的真实运行性能。
- [ ] **并发同步：** 在你的渲染器开发中，如果有多个线程需要同时写入同一个像素颜色值，除了使用 `std::mutex`（可能会带来极大的锁开销），还有哪些更高性能的原子操作 (Atomic) 处理方式？
