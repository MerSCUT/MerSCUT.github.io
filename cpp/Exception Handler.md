# 异常

当调用一个函数内部产生无法在局部处理的异常时,

- 被调用者用`throw` 关键字抛出一个异常, 暗示它无法处理某种类型的异常

  - `throw` 可以作用于任何可以复制的对象, 例如 `int` : `throw 5;`

- 主调用者用 `try{} catch(){}` 结构捕获被调用者抛出的异常, 基本结构如下

  ```cpp
  void main_func()
  {
      try
      {
          float x = div(1., 0.);
      }
      catch(ExceptionType &e)
      {
          // Exception Handler 异常处理
      }
  }
  
  float div(float x, float y)
  {
      if (y == 0) throw Exception("Divided by zero");	// 抛出一个错误
      // 也可以直接 throw 1; 即用1表示错误信息, 或者 throw "Divided by zero"; 抛出字符串
      return x/y;
  }
  ```

  尽管可以`throw` 任何一个可复制的对象, 但是出于代码的可读性以及异常处理的内部实现等原因, 应当定义专属于异常的类/结构体`struct myException`. 

## Noexcept 关键字

该关键字在函数声明时使用, 含义是**程序员向编译器保证这个函数(包括其调用的子函数)不会在执行过程中抛出任何异常**.

这一声明使得编译器可以大胆地优化生成的代码, 而**不必为了保护程序执行而预防, 这样会降低性能**.

- 一个例子是 **移动语义** 下的 构造函数和赋值函数, 正确使用这些函数应当以`noexcept`修饰, 使得编译器敢于使用这些(在编译器看起来)不太安全的函数.



异常是 C++ 中引入的概念, 传统的 C 语言库中的函数大部分都不会抛出异常, (除开`qsort()` 等) 可以放心地在使用这些函数时以 noexcept 修饰自定义的函数.



# 异常保障

引入异常机制的目的是 : **让程序在遇到可预见的错误状态后, 仍能正确的处理并安全地继续执行.**

**异常安全操作** : 若某个操作抛出异常, 被强行停止操作后, 程序仍然处于**有效状态**, 则该操作称为异常安全操作.



有效状态是什么意思?

- **对象有效** : 构造函数已经完成, 且析构函数尚未开始执行的状态
  - 一个类的对象会有某种**不变式**约束, 来规定**什么时候这个对象是有效的/合法的**
    - 例如, 有理数`Rational`类中, 两个成员 `p,q` 表示有理数 $p/q$, 不变式约束即为 `q != 0`. 这个约束条件是一个正确的对象应当成立的,  但这个约束通常很难/无法传递给编译器检查, 因为是否有效是由开发者定义的(写在注释里). 执行某个操作的前后, 对象都应当保持不变式约束, 使得对象有效.



C++ 的标准库中的函数操作可以做到以下几种保障之一 :

1. 对**所有**操作的**基本保障** : 维护所有类对象的**基本不变式** (指执行程序前后, 对象值**可以保证有效/合法性**, 内存没有发生泄露, 但是对象内的值可能逻辑上不正确, 即如果操作中发生错误, 可能无法回滚到之前的状态)
2. 对**关键**操作的**强保障** : 维护一些特殊操作的"**原子性**" (如果成功, 则完全正确, 否则回滚到无影响状态. Commit or Rollback)
   1. 例如 `vector` 对象的`push_back()` 操作.
3. 对**某些**操作的**不抛出保障** : 确保部分操作绝对不会抛出异常, 其方法就是前面所述的`noexcept`修饰符.

但上述保障的前提是, **用户本身的操作是正确的**. 若用户提供的操作本身就会导致资源泄露, 那么自然没有前面的保障这一说.



# 资源管理

当系统的资源(不仅是内存)被程序请求时, 它期望在未来的某个时刻被正确释放. 

内存是最常被使用的资源, C++中的 `new ` 和 `delete`运算符能够申请和释放内存资源.

但是实际编码过程中, 可能由于各种主客观原因, 导致资源并没有正确释放. 例如, 在 `new int[10]` 使用时抛出了异常, 此时程序的控制流不会往下执行到 `delete [] int`, 这会导致十分难以排查的内存泄漏bug.

```cpp
void func(int y)
{
	int* a = new int[10];
    if (y == 0) throw Exception("Divided by zero");
    
    delete [] a;
    
}
```

上述代码中, 若 `y == 0` 成立, 则会直接略过 `delete []a;` 从而导致内存泄露. 容易想到的解决方法是, 在 `if (y == 0)` 的程序流中添加释放语句 `delete [] a; throw Exception("...");` 但是随着需要处理异常增加, 每一次抛出异常都需要释放资源, 这将导致代码量成倍膨胀且可读性下降. 

另一种思路是, 利用**类的构造函数, 析构函数** 以及**局部类对象**来帮我们自动管理资源, 此时资源可以被包装到一个类对象中, 该类称为**句柄类**. 

例如, 在请求文件时使用如下定义的类 :

```cpp
class File_ptr
{
  	FILE* p;
public:
    // 构造函数
    File_ptr(const char* n, const char* a) : p{fopen(n,a)}
    {
        if (p == nullptr) throw runtime_error("File_ptr:Can't open file.");
    }
    // ...
    ~File_ptr()
    {
        fclose(p);
    }
};
```

使用构造函数和析构函数的好处是,当局部对象退出作用域(不论是通过`return` 还是`throw`), 被销毁时, 一定会调用其**析构函数**释放资源. 

另一个关键是**构造函数**. 一个对象在执行完构造函数后应当处于有效状态. 所以若需要申请多种资源, 构造函数应当保证在任何情况下, 都不会出现**"构造了一半的状态"**.

上述方法也是**RAII(Resource Acquisition Is Initialization 资源获取即初始化)**准则的体现 : 利用对象的生命周期来管理资源. 遵循 RAII 准则可以减少发生资源泄露的概率.  `std::unique_ptr` 就是 RAII 应用的一个极好的例子.

在其他语言中 (例如Python) 更常见的异常处理结构是`try-catch-finally`. `finally` 下的代码块无论是否捕获到异常都会执行, 很适合用来**统一释放资源**. 而 `finally` 在 C++ 中的更安全解决方案就是 RAII, 它是一种自动隐式处理资源释放的方法.

> C++ 之父明确表示 : C++ 不引入 `finally` 是因为 **RAII 通常更简洁且性能更好**。

# 强制不变式

当一个函数传入的参数不符合其语义时, 该函数的工作无法正常进行. 例如, 一个求长方形面积的函数`area(int x,int y)` 想正常工作, 需要传入的参数满足`x`和`y`为正数. **对参数的要求称为前置条件**.

而`area()`函数的返回值, 也应当满足"是长`x`宽`y`的长方形的面积"这一层语义, **对返回值的要求称为后置条件**.

通常而言, 

- 函数的**调用者**应当确保传入的参数满足函数的前置条件.
- 函数内部(**被调用者**)负责处理**正确的前置条件**, 返回正确的结果; 当**检查出前置条件不正确时, 采取适当的措施**. 常见的有 : 强制约束前置条件成立, 终止进程运行.



一种检查条件的方法是`assert`(断言)宏, 用于**运行时断言**. `#include<cassert>` 后, 可以用 `assert(expr)` 来约束`expr`条件一定成立. 若不是如此, 则程序会直接终止`abort()`并返回错误信息. 

`assert` 是运行时进行的检查, 通常用来检查**变量的值是否满足条件**等 (跑起来才能发现的错误), 在`Debug`模式下才能启用, 会增加微小的开销. 当

另一个选择是**编译时断言**`static_assert(expr, message)` : 无条件检查 `expr` 的值是否为真, 若为假, 则输出`message` 以及编译错误信息. C++11 后, 可以直接作为关键字使用, 不需要引入头文件.

`static_assert` 是编译时期进行的断言, 通常用来检查**模版类型, 常量表达式**这些在编译时期就可以确定的信息. 若断言失败, 则无法生成可执行文件.



# 条件 noexcept 和 noexcept 运算符

前文提及 `noexcept` 可以在函数声明后修饰, 指明"这个函数不会抛出任何错误", 这暗示了若函数内部真的不巧抛出了`throw`, 程序/编译器都是不会去处理的, 因而会无条件终止程序`terminate()`.

一种更灵活的方法是 : 条件`noexcept` :

```cpp
void my_func(int& x) noexcept(Expr) ;
```

`noexcept(Expr)` 关键字的含义是当 `Expr`为`true`时, 该函数不会抛出任何异常.

另一方面, `noexcept(Expr)` 本身可以是一个**运算符.** (注意辨别用于运算符和关键字时的区别)

`noexcept(Expr)`运算符用于**编译时期**, 其返回值是一个`bool`变量, 其作用是询问**编译器** : 如果我运行`Expr`这个表达式(或者函数), 它是否****可能****抛出异常? 倘若编译器能**十分笃定地判断, 这个表达式不可能抛出异常(例如编译器发现`Expr`声明中包含`noexcept`关键字)**, 那么`noexcept(Expr)` 就会视作`true`进行编译.

常用例 : 

```cpp
void func1() noexcept {}		// 无条件 noexcept 关键字
void func2() {}
void f1() noexcept(noexcept(func1()));	// 第一个noexcept(.) 是条件关键字, 第二个是运算符
// func1() 被声明为 noexcept, 编译器能发现执行 func1(); 不应该抛出异常, 得知 noexcept(func1())为true
// 随后, 条件 noexcept(...) 发现括号内为真, 因此 f1 函数被打上了 `noexcept` 标签.
void f2() noexcept(noexcept(func2())); 
// 同上, 但是 func2() 可能抛出异常 (它没有noexcept声明), 所以noexcept运算符会返回false
```

条件`noexcept`以及运算符`noexcept`在标准库中十分常用.
