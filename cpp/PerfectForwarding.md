# 万能引用

给出如下模版代码 :

```C++
template <typename T>
void func(T&& arg) {
    // ...
}
```

当调用函数传参时, 编译器会根据传入的值来推导类型 `T`. 

编译器中有一条死规矩 : 不允许显式出现**引用的引用**. 在面对 `T&&` 这样的类型推导时, 会遵循以下规则 :

1. 若传入的是**左值**, 例如 `int a = 10; func(a);`, **编译器会将上述 `T` 推导为 `int &`.** 
   1. 为什么不是 `int` ? 若为 `int`, 则 `int && ` 右值引用无法绑定到左值 `a` 中.
2. 若传入的是**右值**, 例如 `func(20);` , 编译器会将 `T` 推导为 `int`.

现在, 第一种情况中, 函数的签名被改为 `void func(int& && arg)`, 当出现多个(左值or右值)引用符号时, 编译器会触发==**引用折叠**== 功能. 核心规则是 : **若多个引用符号中出现了一个左值, 则最终折叠为左值引用. 当所有引用符号全为右值引用时, 最终才折叠为右值引用**.

再看上面两种情况 :

1. 传**左值**, `T` 为 `int &`, 所以 `func(int & &&arg)` 折叠为 `func(int& arg)`, 完美匹配**左值引用**.
2. 传**右值**, `T` 为 `int`, 所以 `func(int && arg)` 不需要折叠, 完美匹配**右值引用**.

上述`T&&` 的用法称为**万能引用**. 它不仅能用在**模版参数**, 只要`T` 的位置**需要编译器类型推导**, 例如 `auto&& v = 20;` 编译器也会根据上述规则推导类型, 并实现左右值引用.

当编译器看到传入的参数后, `T` 就被固定为 `int&` 或 `int`. 更进一步, 万能引用让函数模版 `func` 在编译器通过`T`==**记住了传入的参数最初是左值还是右值**==. 这一点在后面还原类型时很重要.

# 类型退化

上述例子中, 当传入右值 `func(20);` 时, C++ 的核心机制认为, 此时该右值传入了一个**具有名字的变量** `arg` 中. 而只要具有名字, 该值就是**左值**. 此即所谓==**右值退化**==. 

倘若此时我们需要执行其他函数, 直接传入左值 `arg` 可能导致**部分函数放弃使用移动语义**. 例如用拷贝构造替代移动构造, 增多不必要的复制和开销.

所以在传入参数前, 若判断 `arg` 传入前是左值/右值, 那应当将其转换回左值/右值. 

# 完美转发

`std::forward` 就是用来完成上面的任务的. 看下面的示例

```C++
template <typename T>
void func(T&& arg) {
    // 一定只调用左值版本
    other(arg);
    // 根据传入的参数类型调用对应版本
	other(std::forward<T>(arg));
}
void other(int& i);		// 左值版本
void other(int&& i);		// 右值版本
```

通过万能引用, `func` 定义的类型`T` 已经被确定为 `int` (右值) 或 `int&` (左值), 此时传入 `std::forward<T>` 就能将左值变量 `arg` 转为其传入时的类型.

该方法的源码很简单 :

```C++
template <typename T>
constexpr T&& forward(std::remove_reference_t<T>& arg) noexcept {
    return static_cast<T&&>(arg);
}
```

它仍然使用了**引用折叠的原理**. 

1. 当 `T` 为右值 `int`, `forward` 进行了以下操作 :
   1. 以`int&` (左值引用) 接受  `arg`.
   2. 将`arg` 强转为 `<int &&>`, 返回 `arg` 的右值引用版本. 
2. 当 `T` 为左值 `int&`, `forward` 进行了以下操作 :
   1. 以 `int&` (左值引用) 接受  `arg`.
   2. 将 `arg` 强转为 `<int& &&>` , 根据引用折叠也就是 `<int&>`, 返回 `arg` 的左值引用版本.
