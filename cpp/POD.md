# POD : Plain Old Data

2026-3-29 Mergic



笼统地说, POD 类型就是与 C 语言完全兼容的数据类型, 它不包含任何**面向对象**的包袱 (虚函数).

这种类型的好处在于可以使用性能极高的 `std::memset` 和 `std::memcpy` 来管理对象内存.

C++ 11 后, 标准库详细定义了 POD. 只有当同时满足以下两个条件的类型才能称为 POD 类型

1. **Trivial 平凡的** : 类型**没有隐藏的初始化/销毁逻辑**, 其生命周期可以由 `std::memset` 和 `std::memcpy` 来管理. 具体而言 : 
   1. **没有用户自定义/移动/拷贝构造函数** 和 **赋值运算符重载, 析构函数**.
   2. **没有虚函数, 虚基类** : 即没有隐藏成员 `vptr`.
   3. **基类, 非静态数据成员也都是 Trivial**.
   4. **不能有类内初始化** (这条存疑, C++ 14 放宽了条件).
2. **Standard-layout 标准布局** : 类型的**内存排列方式确定**且**与 C 语言的`struct`完全一致**. 编译期不会往对象内存中塞其他东西或改变次序.
   1. **没有虚函数, 虚基类** : 还是 `vptr` 的原因
   2. **所有non-static数据成员有相同的访问权限** : 不能一些`private`一些`public`.
   3. **不能有引用类型的non-static数据成员**
   4. **在一个继承体系中，所有的 non-static 数据成员必须声明在“同一个”类中** : 要么全在基类, 派生类没有; 要么基类没有, 派生类有. 严格限制与 C 语言中的 `struct` 方式一致, 避免复杂的继承关系打乱内存布局.
   5. **所有的基类和non-static数据成员都是 Standard-layout**.



C++ 20 中弃用了 POD 的概念. 实际上我们只需要上述两种性质之一就可以应付大部分场景了 :

1. 满足 Trivial 就可以用 `memset` 和 `memcpy` 达成高性能处理对象.
2. 满足 Standard-layout 就可以传给其他基于 C 语言的平台或嵌入式程序.
   1. 接收方打开箱子后，能“**准确无误地在固定位置摸到”特定的物品（内存偏移定位）**。
