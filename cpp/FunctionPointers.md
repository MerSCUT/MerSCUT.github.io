# 函数指针

## 基本概念

**函数指针指向一段代码的首地址**.

一个函数的**类型Type**是指**返回值类型 + 每个参数的类型**. 

`int a(int, int)` 的类型是 `int (int, int)`. 

只有返回值类型, 参数的个数, 每个参数位置对应的类型**完全一致**, 才认为函数是同一个类型.

## 声明

先看看基础类型是怎么把变量声明改为指针声明的 :

- `int`型变量的声明为 `int a;`
- `int` 型指针的声明为 `int *p;`

函数与函数指针的声明是相同的.  普通函数的声明为 :

```cpp
int add(int, int);			// 注 : 声明可以省略参数名.
```

而函数指针的声明为

```cpp
int (*ptr)(int, int)
```

一个微小的差异在于, **函数指针的声明必须加括号.** `(*ptr)` 不可省略 `()`.

- 因为 C++ 中, **函数调用运算符`ptr()`** 的优先级 $ > $ **指针/解引用运算符 `*ptr`**

所以如果写 `int *ptr(int, int)`, 编译器会理解为 `(int *) ptr(int, int)`. 

> `*ptr` 的优先级不仅比 `ptr()` 低, 还比 `ptr[]` (数组声明) 低.

下面用一个复杂的声明例子 : `double (*config[10])(double);`, 介绍著名的 **Right-Left Rule**, 也可以叫逆时针螺旋法则.

1. 找到变量名 `config`;
2. 第一步**先向变量名的右侧看 (Right)**, 看到了 `[10]`. 
   1. 表明 `config` 是一个包含 10 个元素的数组.
3. 然后看`config[10]` 的**左侧 (Left)**, 看到 `*`.  
   1. 表明 `config[10]` 这个数组中存储的是 10 个指针.
4. 再**往右(Right)**看, 看到了 `(double)`, 是参数列表, 既然有参数列表, **再向左看**一定有返回值类型 ` double`.
   1. 表明 `(*config[10])` 这个存储 10 个指针的数组中, **指针指向的函数类型是`double (double)`**.

至此这个声明被拆解完了. 可以发现读取声明时是**以变量名的右手开始, 一左一右地由内向外解析每个部分**, 并赋予相应的含义.

> 一左一右的部分也可以看成是有一个逆时针旋转的时钟.

对于我们前面看到的函数指针声明, `int (*ptr)(int, int)`, 变量名 `ptr` 的右侧啥也没有 (一个右括弧), 也就是其向右侧解析走不通, 随后向左解析遇到 `*`, 表明 `ptr` 是一个指针. 再向外解析`int (int, int)` 得到 `ptr` 是一个指向 `int (int,int)` 类型的函数指针.

## 调用

首先, 如何给一个函数指针赋值? 看看下面的例子 :

```cpp
bool A(double d) { return true; }
bool B(double d) { return true; }
```

我们可以声明以下函数指针, 并让其指向 `A` (函数签名) :

```cpp
bool (*ptr)(double) = A;
```

通过两种方法, 我们可以用 `ptr` 调用 `A`.

1. 显式调用 : `(*ptr)(0.5);`
2. 隐式调用 : `ptr(0.5);`

前者十分好理解. 但是略显繁琐. 后者是更常见的选择.



# 类内成员函数指针

说清楚点, 标题的意思是 **指向"类内成员函数"的指针**.

我们通常会将函数与数据成员封装成类, 用指针去指向类中的函数是一个常见情景, 但其原生语法同样比较冗杂. 

## 声明

现在我们可以看一看更复杂的例子. 如题, 如果要定义一种指针, 它指向的是**类中的某种类型的成员函数**, 该怎么写?

```cpp
class C {
public:
    void func();
};
```

先公布答案. 要声明一个指向 `func` 的指针, 需要这么写 :

```cpp
void (Material::*methodPtr)() = &Material::sample;
```

引入类作用域符号后, 整个声明看起来更繁琐了. 我们仔细看看每个部分.

当我们在类内声明 `func`, 在**类外定义** `func()` 时, 类外是需要这么写函数头的 :

```c++
void C::func() {}
```

它提醒我们一件事 : **类内的函数成员, 与类外的普通函数在本质上是不同的**. 

- 最直接的差异就在于, **成员函数**的参数需要包括`this`指针**.**

- 也就是说, 编译器眼里, 这个成员函数是 :

  ```cpp
  void C::func(const C* this);
  ```

所以用简单的 `void (*ptr)()` 指向`func` **无法通过编译器检查**.



仿照一开始的思路, 我们将上面的式子改写为指针形式 :

```cpp
void (C::*methodPtr)()
```

请注意, 中间的括号不可删, 变为 `void Material::*methodPtr()`. 

- 这是因为根据优先级, 变量名会率先与函数调用符号结合为`methodPtr()`, 从而报错.

> 你可能会想为什么不是 `void (*C::methodPtr)()`. 该写法确实合法, 但是含义与上面大相径庭.
>
> - 第一步解析出 `C::methodPtr` , 这是访问**静态成员**的写法. 
>   - 表明 `methodPtr` 是一个**静态成员**.
> - 再往外走, 结合 `*`
>   - 表明 `methodPtr` 是一个**静态指针成员**.
> - 再往外走, 结合 ` void ... ()`.
>   - 表明 `methodPtr` 是一个**<u>指向普通函数</u>的静态指针成员**. 函数类型为 `void ()`. 

> C++ 定义了一种合体运算符 `::*`.
>
> `C::*ptr` 告诉编译器 : **这个指针`ptr`必须配合一个`C`类的对象实例才能访问内存地址**. 

有了上述 `::*` 运算符的知识后, 再去解析 `void (C::*methodPtr)()`, 就很简单了

- 第一步解析出 `C::*methodPtr`
  - 表明 `methodPtr` 是**指向类`C`内成员的指针**.
  - 注意 `::*` 直接连起来看.
- 第二步解析出 `void ()`
  - 表明`methodPtr` 是**指向类 `C` 内, 类型为 `void ()` 的成员函数的指针.**

## 调用

我们可以使用以下赋值语句, 让 `ptr` 指向类 `C` 的成员函数 `func()`.

```cpp
void (C::*methodPtr)() = &C::func();
```

怎么通过 `ptr` 调用 `func()` 呢? 一个核心点在于, **如何提供对象实例的信息** ?

很简单, 其他时候, 我们访问数据成员和成员函数都是通过 `obj.member`, `obj.Function()` 进行的. `Function` 中自然有 `obj` 的 `this` 指针. 

到类内的函数指针语境下也是一样的. 其方法是 :

```cpp
(obj.*methodPtr)();
```

有几个点需要注意

1. 我们看到了`.*` 运算符, 它的含义用自然语言表达, 是 **"对象的指针访问成员"** 运算符. 含义就是告诉编译器, 这个运算符前面`obj`是一个对象, 后面是一个访问类内成员的指针`methodPtr`.

2. 事实上, 若将对象 `obj` 改为指针 `C* obj_ptr;` , 还能使用 `obj_ptr->*methodPtr()` 运算符 `->*`.

3. **左侧的括号不能去掉**变为 `obj.*methodPtr()`. 

   原因还是**优先级**, `()` 的优先级非常高, 高于`.*` 和 `->*`. 编译器看到这个表达式, 会先解析 `methodPtr()` 并尝试寻找一个签名为 `methodPtr()` 的函数, 然后报错. 

   因此需要先用括号强行让编译器解析 `(obj.*methodPtr)` 为一个对象的指针访问
