# 类模版

2026-3-24 Mergic

定义类模版的通用语法 :

```C++
template<typename T>		// or <class T> (向后兼容)
class Stack{
	T item[MAX];  
    int top;
    
    bool push_back(int i);		// 在这里直接 inline 定义可以省略下面写的一大堆.
};

// 类外定义 : 类模版 的 "成员函数模版" 的格式要求
template<typename T>
bool Stack<T>::push_back(int i){
    //....
}
```

**类模版** -----实例化-------> **模版类**.

实例化需要**显示指定类型** :

```c++
Stack<int> st;
```

这有别于**函数模版**, 普通的函数模版可以由编译器隐式实例化, 因为**编译器可以得知要传入的参数类型**.



STL 中常见的另一种模版定义 :

```C++
template<typename T, int n>
class array{
  	T a[n];
    
    //... 成员方法
};
```

注意模版头 : `template<typename T, int n>` 中包含了 `int n`, 这种称为**非类型(non-type)参数** 或 **表达式参数**.

当传入不同的参数时, 例如传入

- `array<int, 5>`
- `array<int, 7>` 

会产生两个不同的模版类.

非类型参数的使用是有限制的. 例如上例中的 `n` 必须是常量或者 `constexpr`. 类中的方法也不允许对 `n` 进行修改.

对比一下另一种实现方案 :

```C++
template<typename T>
class array{
	T* a;
	
	array(int n){
		a = new T[n];
	}
}
```

即通过**构造函数**来传递数组的大小`n`. 这是容易想到的一种方案, 但是与前一种表达式参数化方案相比, 这里的 `a` 是用`new`操作符在**堆**上创建的. 需要在程序中显式执行 `delete` 来进行管理. 而将`n`作为模版参数传入, 可以直接创建**栈**上的数组`a[n]`. 

表达式参数化方案也有缺点 :

1. **每种数组大小 $n$ 都会产生自己专属的模版类定义**.
2. 构造方法不通用, 不同数组大小的数组变量之间的交互灵活性会下降.



另一个特性是 : **类模版的<u>类型参数</u>可以有默认类型值**.

```C++
template<typename T1, typename T2 = int>
class myClass{
  	//...  
};
```

这个特性在**函数模版**中不成立. 但是函数模版可以指定**non-type参数**



# 具体化

一个模版类在不被某个对象声明所需要时, 编译器不会主动生成类定义.

当声明模版类对象时, 编译器会产生**隐式实例化** :

```C++
array<int, 4> ar;
```

编译器发现有个对象 `ar` 需要 `Array<int, 4>` 这个类, 于是会生成这个模版类的定义.

这种方式称为**隐式实例化**.

相对应的**显式实例化**, 则是在代码中直接指明自己需要实例化的模版类

```C++
template class array<int, 4>;
```



有时, 一个类模版定义无法顾及所有数据类型的情况. 此时就需要对某些**特定的数据类型进行自定义修改**. 例如, 对于一个自动排序的数组容器类, 数值类型的序关系定义可以完美兼容. 但是对于字符串`string` 或者另一个自定义类`T`, 就需要额外补充自定义的排序规则.

**具体化模版**就是针对那些**通用泛型类无法解决的情况**所写的特殊版本. 语法如下 :

```C++
struct Pack{
	int x;
	int y;
}
// 具体化包含 <> 以及后文 {} 的具体化逻辑
template <> 
class array<Pack, 4>{
	// 例如排序算法定义为先x后y的逻辑
    void sort(){
        //...
    }
}
```



同时, 对于有**多个模版参数的类模版**, 还可以实现**部分具体化**.

```C++
// 通用模版定义
template<typename T1, typename T2>
class Scene{
    
};
// 部分具体化
template<typename T1>
class Scene<T1, int>{
    
};
// 完全具体化
template <>
class Scene<char, int>{ 
    
};
```

从上可以看出, 具体化允许将**任意个参数确定, 其余参数保留为模版参数**, 然后重新定义具体化模版中的特殊逻辑.



当有对象声明为 `Scene<char,int>` 时, 编译器会从**最具体**的模版开始比对, 直到**最通用**的泛型模版.
